# Set 1 — the two-stage selected feature set

Generated by `scripts/build_set1.py`. Do not hand-edit — rerun the script.

Resolves [#12](https://github.com/jenujari/prdict-pov-v1/issues/12) (map decision 7). Set 1 is the correlation-pruned, target-ranked feature set; [set 2](https://github.com/jenujari/prdict-pov-v1/issues/13) is the PCA alternative. Both feed the three-model scorecard, so set 1 is fixed here as one artifact.

## Parameters

**Stage 1 — redundancy prune.**

- Metric: **Spearman** `|rho| >= 0.95` over the 199 numeric features (cyclic + linear_numeric). Rank correlation catches the monotone redundancy Pearson would miss and that an ordinal category code makes meaningless.
- Survivor rule: **higher mean-horizon mutual information** — variance cannot discriminate after standardisation.
- Atomic units: **sin/cos pairs (#7)** — a pair is kept or dropped whole.
- categoricals/booleans bypass the prune; #15 decides those per model.

**Stage 2 — target ranking.**

- Metrics: **mutual information** + **Spearman**, mean over the 10 step-return horizons.
- Selection gate: a **target permutation** null (12 shuffles, p95 band). A feature is selected only if its mean mi exceeds the null band.

**Fold stability — majority-frequency union.** Each fold selects in-fold (selection is fit in-fold for scoring; set 1 is the reported union); set 1 is the union of features chosen in at least **3 of 5** folds.

## Reading the result

astro-vs-return MI sits at the noise floor by design; the null band is the honest line, and how many features clear it is the finding — not a threshold tuned to produce a set.

Across folds the strongest single-feature MI is **0.097763** against a null p95 of up to **0.02644**. That relationship — not any one selected column — is the result #12 hands to the model tickets: it fixes, in advance, what 'the astro features carry almost nothing linear about returns' looks like in numbers.

## What the models consume

Set 1's numeric part is model-agnostic (rank/MI are scale-free, so no fold scaler is needed to choose it). The **categorical** part of each model's input is not selected here — it follows #15: the TFT keeps the sharp bins as embeddings, XGBoost drops them. XGBoost additionally collapses the day-lag collinearity of set 1's features when it flattens the 90-session window; that flatten-level prune is an XGBoost training step (#38) over these features, not a second definition of set 1.
